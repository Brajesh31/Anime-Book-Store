# Contributing

Contributions should keep the application understandable and safe to run locally.

- Keep frontend and backend changes focused and document API contract changes.
- Use Mongoose validation, parameterized/validated IDs, and explicit error responses.
- Do not commit MongoDB URLs, credentials, dumps, `node_modules`, build output, or personal data.
- Add loading, empty, validation, and failure states to new UI flows.
- Run frontend lint/build and exercise affected API endpoints against a disposable database.

Pull requests should describe schema changes, routes, environment requirements, validation, and screenshots for UI changes.
