# 🆘 Support and help

This repository provides a small book catalogue CRUD application. Use the resources below to diagnose issues before opening a request.

## 1. Self-service resources
1. [README](./README.md): project scope, features, and quick start.
2. [Installation](./docs/installation.md): first-time local setup.
3. [Development](./docs/development.md): daily developer workflow.
4. [API reference](./docs/api/README.md): endpoint behavior and response shapes.
5. [FAQ](./docs/faq.md): common questions and scope clarifications.
6. [Troubleshooting](./docs/troubleshooting.md): setup and runtime diagnosis.

## 2. Report a bug
Use the GitHub bug report issue form. Include the affected page or endpoint, steps to reproduce, expected behavior, actual behavior, environment versions, and redacted logs.

A useful bug report should let another developer reproduce the problem without access to your machine or private database.

## 3. Request a feature
Use the feature request form. Explain the user problem, proposed behavior, acceptance criteria, affected area, and any data/API implications. Search existing requests before opening a duplicate.

## 4. Documentation correction
Use the documentation issue form. Identify the file/section, explain what is inaccurate or missing, and propose the correction.

## 5. Security issue
Follow [SECURITY.md](./SECURITY.md) and report privately. Never post database URLs, credentials, tokens, dumps, or private records in public issues.

## 6. Information to include
- Operating system and Node/npm versions.
- Commands run and the directory where they were run.
- Relevant request method/path/status.
- Redacted console output.
- Whether MongoDB is local or hosted.
- Whether the issue is reproducible from a clean install.

## 7. Information to exclude
Do not include complete connection strings, passwords, API tokens, private user data, database exports, or unredacted logs. A credential-bearing URI was previously committed publicly; do not reuse or repeat it.
